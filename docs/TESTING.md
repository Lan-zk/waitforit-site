# 测试策略

## 为什么需要 E2E

本项目同时包含 Payload、Next.js Server Components、浏览器交互、SQLite、文件系统内容和
WebGL。单元测试或 Local API 集成测试只能证明其中一部分逻辑正确，不能证明访客实际走过
的完整链路可用。

E2E（End-to-End）从浏览器出发，经过真实 Next.js 路由、Payload 查询、服务端渲染、
客户端 Hydration、Cookie、CSS 布局和用户交互，再验证最终页面。它主要防止以下问题：

- App Router 目录或动态参数正确，但真实 URL 仍然返回 404。
- Payload 查询正确，但 Server Component 没有把结果渲染到页面。
- 语言状态在服务端正确，浏览器提交表单或刷新后却没有持久化。
- Markdown 能生成 HTML，但图片路由、外部链接或移动端宽内容在浏览器中失效。
- Three.js 代码能够编译，但 WebGL 初始化、Raycaster、触控、Context 恢复或降级导航失效。
- Admin Local API 测试通过，但真实登录、列表和编辑页面无法使用。
- CSS 静态检查正常，但 `390x844` 视口产生横向溢出、不可见焦点或无法操作的控件。

因此 E2E 是公开体验的发布门禁，不是“已有集成测试后的重复检查”。

## E2E 不替代什么

E2E 运行慢、失败现场复杂，不适合穷举数据和边界条件。本项目按下列层次分工：

| 层次 | 主要职责 | 典型内容 |
| --- | --- | --- |
| 纯函数/组件测试 | 快速验证确定性转换和渲染 | locale 回退、Markdown JSX、Lexical JSX |
| Payload 集成测试 | 验证模型、Access、关系、SQLite 写入 | `writings`/`series` 约束、同步增删改 |
| 常规 E2E | 验证浏览器中的主要用户旅程 | 首页、语言切换、博客、小说、Admin、404 |
| 隔离运行时 E2E | 验证跨进程和文件系统发布链路 | 运行中新增、修改、删除 Markdown |

边界条件优先放在集成测试；每条关键用户旅程至少保留一条浏览器 E2E。

## 当前测试套件

### 集成测试

目录：`tests/int/`

```bash
npm run test:int
```

当前覆盖：

- 内容仓库扫描、Frontmatter 和重复章节校验
- 路径穿越、绝对路径、反斜杠和符号链接拒绝
- Markdown 与受控图片路径读取
- `writings` / `series` Access、关系和字段校验
- 元数据新增、更新、删除及写入前完整校验
- Commit SHA 未变化跳过、失败不推进状态和重试
- Markdown、Lexical 与国际化渲染
- Resume 结构化模块、可信写入、匿名读取和匿名修改拒绝
- 公开导航过滤摄影入口，以及 HTTP/HTTPS 外链规范化

### 常规浏览器 E2E

目录：`tests/e2e/`

```bash
npm run test:e2e
```

当前覆盖：

- Payload Admin 登录、列表和编辑页
- 简体中文默认值、英语切换、Cookie 持久化和非法值回退
- 博客列表、GFM 正文、相对图片和 404
- 博客 Side Rays、小说 Galaxy、减少动态效果静态降级
- 小说作品、章节顺序、章节导航和移动端宽内容
- 项目详情封面与摘要、摄影入口隐藏
- WebGL 初始化、卡片跳转、无 WebGL 降级、响应式断点、Context 恢复、
  触控拖动和键盘入口

### 运行时内容 E2E

目录：`tests/e2e-runtime/`

```bash
npm run test:e2e:content-runtime
```

该套件使用 `test-results/runtime-content/` 下的临时内容仓库和 SQLite，并启动独立的
`localhost:3100` 开发服务器。它不应读取或修改真实 `dev.db` 和发布仓库。

## 测试数据约束

测试只有在输入可复现时才有发布门禁价值。

- 集成测试必须创建自己的临时目录或清理自己写入的记录。
- 运行时内容 E2E 必须继续使用独立数据库和内容仓库。
- 常规 E2E 当前通过 `.env` 使用开发数据库和相邻内容仓库；这是已知技术债，不能把某台
  开发机上的通过结果直接等同于干净环境可复现。
- 常规 E2E 后续应增加专用 fixture 准备步骤，显式创建项目、媒体、博客、小说和 Resume
  空状态数据。
- WebGL 断言必须先等待场景明确进入就绪状态，再检查可见实例或执行 Raycaster 操作；
  不应依赖固定延迟猜测纹理和入场动画已经结束。
- 测试失败时保留 Playwright error context；重试只能用于收集 trace，不能用来掩盖稳定
  失败。

## 完成判定

前端功能不能只凭“代码已写完”标记完成。至少需要：

1. 相关集成测试通过。
2. 对应浏览器用户旅程通过。
3. 桌面和 `390x844` 移动布局经过验证。
4. 键盘操作和可见焦点经过验证。
5. 浏览器控制台没有未解释错误。
6. 涉及 WebGL 时，无 WebGL 降级和场景交互均未回归。

`npm run check` 覆盖 lint、类型生成、集成测试和生产构建，但不包含 E2E；它不能单独作为
前端体验完成的证明。
