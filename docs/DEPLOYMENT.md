# Deployment

## 原则

- 代码通过 Git 和不可变镜像发布。
- `.env`、SQLite、媒体和备份留在部署环境。
- 生产 `PAYLOAD_SECRET` 使用独立强随机值，不能复用本地或 CI 值。
- 数据库迁移在切换新版本前执行，并先备份数据库与媒体。
- 应用端口仅绑定回环地址，通过反向代理提供 HTTPS。

## 建议流程

1. CI 完成 lint、类型生成校验、集成测试、浏览器测试和生产构建。
2. 备份当前 SQLite 数据库和媒体目录，并验证备份可读取。
3. 拉取或构建目标版本镜像。
4. 使用生产环境变量运行 `npm run payload -- migrate`。
5. 启动新版本并检查首页、`/admin` 登录、内容读写和媒体访问。
6. 反向代理切换流量；失败时恢复旧镜像和对应备份。

仓库内的 Compose 是本地容器验证基线，不包含生产证书、域名、反向代理或服务器专属路径。
生产部署文件应在确认现有服务器的服务管理方式、挂载和备份策略后单独落地。

## 现有服务器数据库升级

现有服务器数据库已经记录 `20260727_101632_initial`。仓库保留该历史迁移，并通过
`20260728_000000_bridge_initial_schema` 补齐 Projects、Photography、Globals、媒体派生字段
和旧发布模型前置表，再顺序执行 Git 内容模型与结构化 Resume 迁移。

- 迁移前停止应用，并把 SQLite、媒体目录和运行环境配置作为同一恢复单元备份。
- 必须先在该数据库的副本上运行完整迁移，并核对用户、媒体和迁移记录。
- 正式迁移失败时停止切换，恢复部署前数据库与媒体备份；不要只回退应用镜像。
- 全新数据库从 initial 开始执行同一迁移链，不依赖开发环境 schema push。
